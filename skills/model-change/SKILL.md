# /model-change — 新模型上線盤點

新模型上線時，把「哪些地方要跟著調整」找齊：一支不改檔的掃描器列出寫死的模型 ID 與沒寫模型的無頭呼叫，一張十類檢查表補上掃描器看不到的部分，最後整理成一份給使用者決定的清單。**只盤點，不自己改設定；每一項改動都要使用者確認。**

> 🤖 R2-D2 時刻：千年鷹號的超光速引擎明明修好了，一拉桿還是沒反應。原因不在引擎：它被人從別處關掉了。全船只有 R2 知道，因為牠剛剛才問過雲城的中央電腦。換了新零件之後出問題的地方，常常不在你修的那一處。

## 為什麼需要

新模型一上線，直覺是把設定檔裡的型號換掉。實際上會漏的通常不在你記得的地方：

- 某支排程腳本的**部署副本**還寫著舊 ID（repo 改了，正在跑的那份沒改）。
- **沒寫模型的無頭呼叫**吃的是預設模型，預設一換，它就跟著換，而且通常換成最貴的那個。
- **effort 的預設值跟著型號走**：只換 ID 不寫 effort，等於同時改了兩件事。
- 記帳用的價目表、白名單、測試裡的 ID 沒跟上，數字悄悄變成錯的。

這些地方不會自己報錯。這支 skill 把找的動作拆成兩半：掃描器做機械比對，agent 照檢查表補上要讀文件、要跑探針才知道的部分。

## 常數區

| 項目 | 值 |
|---|---|
| 掃描器 | `python3 <本skill目錄>/scripts/model_audit.py`（純標準庫、不連網、內建 `--selftest`） |
| 掃描範圍（預設） | `~/.claude`（不含 `projects/` 底下的對話紀錄）、`~/.claude/projects/*/memory/*.md`、目前目錄。⚠️ 看不到放在別處的啟動腳本與排程腳本 |
| 掃描範圍（自訂） | `--roots-file roots.json`，格式見掃描器檔頭說明 |
| 產出 | 決策清單一份；落點由使用者指定，沒指定就放目前專案目錄 |

## 步驟

### 0. 抓官方文件原文

用 `curl` 把官方文件的 Markdown 原文抓下來存檔，不要用會摘要的抓取工具：摘要說「頁面上沒有」不算查過。要抓兩類：

- ① 模型總表、價格、退役時程（API 平台文件）。
- ② Claude Code 的模型設定頁與環境變數頁：別名對應哪個型號、最低 CLI 版本、effort 預設、自動壓縮門檻。

⚠️ API 平台頁與 Claude Code 頁講的是不同產品，同一個設定的預設值可能不同，記錄時標明來源。型號與價格一律以當天查到的原文為準，不要憑記憶，也不要從「清單上沒看到」推論某個模型不存在。

找頁面的起點是兩份純文字索引，裡面列的就是每一頁的 Markdown 原文網址，從裡面挑要抓的頁：

```bash
curl -fsSL https://platform.claude.com/llms.txt -o platform-index.txt      # ① API 平台文件
curl -fsSL https://code.claude.com/docs/llms.txt -o claude-code-index.txt  # ② Claude Code 文件
```

網址會搬家：索引抓不到就從官方文件首頁找當天的位置，別沿用舊筆記裡的連結。

### 1. 跑掃描器

```bash
python3 <本skill目錄>/scripts/model_audit.py \
  --current <現役完整 ID，逗號分隔> --legacy <仍可用的舊 ID> \
  [--roots-file roots.json] [--json report.json] [--no-text]
```

- 掃描器**不內建模型清單**，現役與舊型號由你從第 0 步的原文抄給它。
- 排程腳本、常駐啟動腳本、launchd 或 systemd 設定在預設範圍以外的話，寫一份 `roots.json` 把它們列進去。🔴 範圍要包含**部署副本**，不只 repo。
- 🔴 **D 段或 E 段是 0 處，先懷疑範圍沒涵蓋，不要當成沒有。** 預設範圍看不到家目錄與系統排程目錄裡的腳本，掃不到的結果一樣是結束碼 0。先查它們實際放在哪（`crontab -l`、launchd 或 systemd 的設定目錄、家目錄下的啟動腳本），列進 `roots.json` 再跑一次。
- 多台機器各跑一次。
- 先看結束碼：`0` 正常；`3` 掃描不完整（根目錄不存在、掃到 0 個檔、有檔案或目錄讀不到），先修路徑或權限，這時的結果不可信；`4` 掃描完整但 `--json` 寫不出去。
- 結束碼 `3` 常常只是權限：掃家目錄這種大範圍時，系統保護的目錄會列不出來，A 段印出是哪一個、什麼原因。確定不必掃的，在 `roots.json` 那個根目錄加 `"skip_dirs": ["目錄名"]` 明寫排除再跑。唯一內建不進去的是家目錄正下方的系統垃圾桶 `~/.Trash`，A 段會印出來；別處同名的目錄照掃。同一份 `roots.json` 在終端機與桌面版 app 裡權限可能不同，換環境要重看結束碼。
- 🔒 報告會帶指令原文的片段（已遮掉看起來像機密的值，但不保證遮乾淨）。要把報告貼到別處或存成 CI 產物時加 `--no-text`。

輸出五段：

| 段 | 內容 | 怎麼讀 |
|---|---|---|
| A | 每個根目錄掃了幾個檔、略過了什麼 | 🟡 的略過（太大、連結指到根目錄外、不是 UTF-8、家目錄的系統垃圾桶）是照規則略過的，數字不合理就回頭看；連結要跟就加 `--follow-links`。🔴 的列不出來與讀不到會附路徑與原因 |
| B | 各區出現的完整 ID，分現役、legacy、不認得 | 「不認得」不等於錯：新模型、打錯的 ID、雲端平台包裝過的 ID、網址片段都會落在這裡 |
| C | 程式與設定檔裡的非現役 ID（檔名與行號） | 這是第 3 步第 2 類的原料 |
| D | 無頭呼叫（`claude -p`）有沒有寫 `--model` 與 `--effort` | 分「確定」與「不確定」兩組，見下 |
| E | 常駐啟動指令（`claude --model …`）用的模型 | 長時間開著的 session 要重啟才會換。0 處先確認範圍 |

D 段把一條指令當成一個單位來看（續行、括號、清單都先組起來），旗標不會借到隔壁那條指令的。它看不出來的不會歸為安全，另列在「不確定」：字串裡的指令（看不出有沒有被執行）、有 `-p` 但執行檔是變數或名稱認不得、引號或括號沒對上的檔。🔴 **「不確定」每一筆都要人打開原始碼看**，不能當成沒事。

兩種東西只計數不列，位置都在 `--json` 裡：訊息與說明文字裡單純提到 `claude -p` 的（`mentions`）；`.md` 與 `.txt` 裡提到的（`doc_mentions`，文件一律不判讀）。⚠️ 會被 agent 或人照著執行的指令文件（skill、runbook）屬於後者，要自己打開看。

⚠️ 掃描器只認**完整 ID**。設定裡寫別名（檔位名稱）的地方它不會列在 B、C 段，那是第 3 步第 4 類要用探針確認的事。

### 2. 先看用量在哪

改之前先看最近兩週的 token 用在哪個模型、哪個來源。最大的一筆常常不在你以為的地方：另一台機器、桌面版的長對話、某支每晚跑的排程。

本機 transcript 裡每則回應都有模型與用量。🔴 同一則回應會拆成多行、每行帶同一份用量，加總時**同一個回應 ID 只算一次**，否則數字會灌水。有裝 `mission-log` 的話，它的收割器已經照這個口徑列出每個 session 的 token 與用過的模型，可以當起點；沒裝也沒關係，自己照上面的口徑加總即可。

### 3. 照十類檢查表寫清單

每一類寫三件事：**現況**（附掃描結果或執行紀錄當證據）、**要不要動**、**需要使用者決定什麼**。查不到的寫「查不到（原因）」，不要留白。

| 類 | 要查什麼 |
|---|---|
| 1. CLI 版本 | 每台機器、每支常駐程序**實跑**的 CLI 是否達到新模型的最低版本。太舊時輸出上限與 context 視窗會退回保守預設。長時間沒重啟的程序跑的是啟動當下那一版，不是現在裝的那一版 |
| 2. 寫死完整 ID 的地方 | 啟動腳本、排程腳本、無頭呼叫、白名單、價目表、測試。來源＝掃描器 C 段 |
| 3. 沒寫模型的無頭呼叫 | 會吃使用者設定的預設模型，通常是最貴的那個。來源＝掃描器 D 段 |
| 4. 別名實跑哪一版 | 檔位別名跟著 CLI 版本走。各跑一支最小的無頭探針，看輸出裡實際的模型 ID |
| 5. 價目與記帳 | 你自己的成本估算表、用量報表有沒有新型號；舊資料不重算時標明價目版本 |
| 6. effort 預設 | 新舊型號的預設 effort 可能不同。只換 ID 不寫 effort，等於同時改了兩件事 |
| 7. context 與壓縮 | 視窗大小與自動壓縮門檻變了，長時間常駐的 session 會長到多大 |
| 8. 快取 | 每個模型各有快取，切換後下一則要整段重寫；無頭執行用的快取時效與價格 |
| 9. 實際用量在哪 | 第 2 步的結果 |
| 10. 退役與降級 | 舊型號的退役日；自動降級會落到哪個模型，那個模型有沒有在你的白名單與價目表裡 |

### 4. 確認後才改，一次一個變數

把清單交給使用者，🔴 **等明確確認才動手**。動手時：

- 省錢估計只能寫「同樣用量換價目重算」，不要當成預期節省：換模型後回合數、輸出量、重試次數都可能變。
- 每一項：改前備份、寫下回滾指令、寫明成功判準（結束碼、log 關鍵行、產物）。
- 同一支工具要改好幾樣時分次上。模型、工具清單、快取時效同一天一起改，壞了分不出原因。
- 無人看管的排程先挑影響最小的一支試一輪。
- 無頭腳本換 ID 時把 effort 一起明寫。✅ 從執行紀錄確認**實際生效的值**，不要只確認參數有傳。
- ✅ 改完重跑一次掃描器，C 段與 D 段對得上清單才算做完。

## 掃描器的自我檢查與限制

改了掃描器先跑 `python3 <本skill目錄>/scripts/model_audit.py --selftest`（合成資料、不連網、自己清暫存）。

它對自己的四個要求：

1. 每個根目錄都印掃了幾個檔、略過了什麼；不存在、0 個檔或讀不到就回結束碼 3。「沒掃到」不該看起來像「沒問題」：用預設範圍時報告會明講它看不到哪裡，D、E 段是 0 處時會提醒先確認範圍。
2. 不內建模型清單。工具不會拿過期的清單替你判斷。
3. 不認得的 ID 獨立一類照樣列出。
4. 看不出來的列「不確定」，不歸為安全。

已知限制：

- 帶日期尾碼的 ID 是去掉尾碼後比對的，日期打錯看不出來。
- 指令先存進變數再補旗標的，只往後找同名變數的 `+=` 與 `extend`／`append`／`push`，而且不看條件成不成立（報告標「後面才補，要看條件」）；其他組法會被報成「沒寫 model」，要人看。
- YAML 一行一個參數的清單寫法認不到；JS 的 regex 字面值、template 與 python f-string 裡的運算式沒有另外處理，藏在裡面的呼叫可能漏掉。
- 太大的檔（超過 1.5 MB）不讀、不是 UTF-8 的檔替換壞字元後照讀：A 段有計數與路徑，但不影響結束碼。
- 遮機密靠樣式比對（長串英數、`token=…` 這類鍵值、網址帳密），不保證遮乾淨；`--json` 報告建立時權限是 0600，要分享前自己再看一次。
- 沒有防「掃描途中檔案被換成連結」這種刻意攻擊；請掃自己信得過的目錄。
- 掃描器自己與它的測試檔不享有豁免，跟別的檔一樣被掃；它的自測資料在執行時才拼出來，原始碼裡沒有會被判讀的字面，所以裝了幾份副本都不會出現在報告裡。0.9.0 的副本還留著那些字面，被掃到時會出現在 C、D 段（檔名是 `model_audit.py`、內容是 `w("runners/…` 這類自測資料），那是誤報，把舊副本更新或移除即可。

## 🚦 鐵則

- 🔒 **只盤點，不改設定**：掃描器不改任何被掃的檔，agent 也不在使用者確認前動任何設定。
- 🔴 **型號、價格、預設值一律以當天抓的官方原文為準**，不憑記憶；「清單上沒看到」不能推論「不存在」。
- 🚫 **結束碼 3 的結果不拿來下結論**：先修路徑或權限，或把確定不必掃的目錄明寫進 `skip_dirs`，再跑。
- 🔴 **0 處先懷疑範圍**：D 段、E 段是 0 時，先確認根目錄涵蓋了部署副本，再相信這個數字。
- 🔴 **「不確定」不是「沒問題」**：每一筆都要人看過原始碼才能劃掉。
- 📝 **一次改一個變數**，每一項都有備份、回滾指令與成功判準。
- ✅ **驗證實際生效的值**：從執行紀錄看模型與 effort 真的是你寫的那個，別信「參數有傳」；改完重跑掃描器。

## 進階：接上你自己的任務系統

檔案版（一份決策清單）是零依賴的最小公倍數，不是天花板。

- 有任務系統的：決策清單落成一張卡或一份共用文件，每一類一個勾選項；「盯第一輪無人看管的排程」排成隔天的提醒。
- 有用量報表的：第 2 步直接讀你的報表，口徑照樣要確認「一則回應只算一次」。
- 有部署清單的：把清單上的路徑直接轉成 `roots.json`，以後每次換模型重用同一份。
